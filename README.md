# x3tif

Sigma Foveon の RAW(`.x3f`)を、**見た目に近い仕上がりの 16bit TIFF へ変換する**小さなデスクトップアプリです。
ウィンドウに X3F ファイルをドロップすると、プレビューを見ながら調整して、同じフォルダに `.tif` を書き出せます。

## 対応機種

- dp Merrill(dp1/dp2/dp3 Merrill)
- dp Quattro(dp0/dp1/dp2/dp3 Quattro)
- sd Quattro / sd Quattro H

SD9〜SD15、SD1 など旧世代の X3F は対象外です(変換せず、エラーを表示します)。

## 出力

- 16bit・3 チャンネル(R, G, B = 下層・中層・上層)のリニア RGB TIFF。Deflate 圧縮(ロスレス、水平差分の予測付き)で、
  非圧縮に比べて約 45% 小さくなります(dp0 Quattro: 130MB → 74MB)。展開すると画素値は元と完全に一致します。
- 出力モードは 2 つ(ウィンドウで切り替え、既定は見たまま):
  - **生データ**: 現像しません(黒レベル減算、ホワイトバランス、色変換、ガンマなし)。位相差検出用の画素の抜けもそのまま再現されるので、
    仕上げ用途には向きません。センサー値を、ビット深度分だけ
    左シフトして 16bit 全域に広げるだけです(14bit なら ×4、無損失)。倍率は XMP の `x3f:RawScale` に記録します。
  - **見たまま**: 黒レベル減算、ホワイトバランス(ファイルの設定)、色マトリクス、露出補正、緩いS字トーンカーブ、
    ガンマを適用した 16bit TIFF です。色空間は sRGB(既定)か Adobe RGB を選べ、選んだ色空間の ICC プロファイルを埋め込みます(生データには埋め込みません。XMP の `x3f:ColorSpace` にも記録)。DP Merrill は CAMF の表で周辺の光量落ちと色かぶりを補正します。露出は既定で「自動」(ファイル内の JPEG プレビューと同じ明るさに合わせる。Photo Pro の出力と比べて合わせた機種は固定値で、sd Quattro は +1.0 EV、dp0 Quattro と DP1 Merrill は 0 EV。この 3 機種はトーンカーブも Photo Pro から測ったもの)で、
    スライダーで −4〜+4 EV を手動指定もできます(値は XMP の `x3f:ExposureEV`)。色味はプレビューと一致しない場合があります。
    SIGMA Photo Pro の出力とは画素単位では一致しません(どの程度の差かは「検証」を参照)。出力は有効画像領域(遮光帯を除く)に切り出します。校正値が無いファイルは、生データのみ変換できます。
  黒レベル等の係数は XMP に入っているので、生データは Lightroom / Capture One / darktable 等で現像できます。
- メタデータ:
  - 標準タグ: 機種名、撮影日時、向き(Orientation)
  - EXIF: 絞り、露出時間、ISO、露出補正、焦点距離(取得できたもの)
  - XMP(`x3f:` 名前空間): X3F の PROP と CAMF(WB ゲイン、色マトリクス、有効領域、RawOffset など)
    ※ バッドピクセルマップなど大きなテーブルは含みません。

### Quattro について

Quattro 世代は、上層がフル解像度で、中層・下層は縦横 1/2 の解像度です。出力は上層の解像度に合わせ、
中層・下層を**双一次補間で 2 倍に拡大**したものです。補間で元の情報が増えるわけではありません。
また、出力は下層が覆う範囲(KeepImageArea)に切り出します。上層の右端にある余分な列は含まれません。

## 使い方

[Releases](https://github.com/7thCode/x3tif/releases) からインストーラをダウンロードして起動し、
X3F ファイルをウィンドウにドロップします(複数可)。右の一覧からファイルを選ぶと、縮小したプレビューが出ます。

- **見たまま**: WB、色空間(sRGB / Adobe RGB)、露出(自動または手動)、赤・青の強さ、トーンを調整できます。Photo Pro は撮影時の色空間の設定に従うので、Photo Pro の出力と揃えたいときは撮影時と同じ色空間を選びます(Quattro の X3F からは撮影時の設定を確実に読めないため、自動では選びません)。プレビューは常に sRGB で表示します。プレビューは表示用に縮小した画像で、ピントや粒状感の確認には使えません。「保存」で選んだファイル、「すべて保存」で一覧の全ファイルを、いまの調整で書き出します。
- **生データ**: 調整は適用せず、センサーの値のまま書き出します。
- 「既定値として保存」で、WB・色空間・赤・青・トーンの調整を次回以降の初期値にします(保存先はアプリの設定フォルダの `settings.json`)。「標準に戻す」で、較正済みの初期値に戻ります。露出はファイルごとの値なので、既定値には含まれません。
- 既存の `.tif` は上書きせず、`-1`, `-2`… を付けて保存します。

## ビルド

Rust(stable)と Node.js が必要です。

```bash
npm ci
npm run tauri -- build      # 開発時は npm run dev
cargo test                  # テスト(コアライブラリとアプリ本体)
cargo clippy --workspace --all-targets
cargo fmt --all --check
```

`npm run tauri -- build` の release ビルドはサイズ優先(`opt-level = "z"` + LTO)なので時間がかかります。

コアライブラリには検証用のコマンドラインツールが 2 つあります(アプリには含まれません)。

```bash
# X3F → TIFF(生データ / 見たまま [露出 EV])、または縮小プレビューの PNG
cargo run --release -p x3tif-core --example x3tif -- in.x3f out.tif developed
cargo run --release -p x3tif-core --example x3tif -- in.x3f out.tif developed auto adobe   # Adobe RGB で書き出す(ev は数値か auto)
cargo run --release -p x3tif-core --example x3tif -- in.x3f out.png preview
# 2 つの 16bit TIFF を画素単位で比べる(下の「検証」)
cargo run --release -p x3tif-core --example tiffcmp -- photopro.tif x3tif.tif
```

構成:

- `core/` — X3F の解析・デコード、TIFF 書き出し(外部依存なしの Rust)
- `src-tauri/` — Tauri アプリ本体(ドロップ → プレビュー → 調整 → 保存)
- `src/` — 最小の UI(`index.html` のみ)

## 検証

### デコード

デコード結果は、参照実装 [x3f_tools](https://github.com/Kalpanika/x3f) の `x3f_extract -unprocessed` と比較しています。
dp Merrill は全ピクセル一致、dp Quattro は最上層が全ピクセル一致、下 2 層は独立に計算した双一次補間と一致しました。
sd Quattro は参照実装が読み込めないため、画像として破綻していないことを目視で確認しています。

### 「見たまま」と SIGMA Photo Pro の比較

同じ X3F から Photo Pro が書き出した 16bit TIFF と、x3tif の「見たまま」の TIFF を、`tiffcmp`(`core/examples/tiffcmp.rs`)で
画素単位に比べます。

```bash
cargo run --release -p x3tif-core --example tiffcmp -- _P0Q0298_photopro.tif _P0Q0298_x3tif.tif
```

出力は 4 つに分かれます。

- **Photo Pro の現像設定**: 参照 TIFF の MakerNote に Photo Pro が残した値(露出・コントラスト・彩度・シャープネス・WB・
  カラーモード・色空間・ノイズリダクションなど)。設定が読めない TIFF は参照に使いません。
- **メタデータの違い**: TIFF / EXIF タグの差。画素の差とは別枠です。
- **画素の差**: チャンネルごとの完全一致率、±1(16bit)・±1/255・±4/255 以内の割合、最大誤差、平均差、MAE、RMSE、PSNR、
  R−G / B−G のずれ。RMSE は「16 画素四方の平均の差(色・トーン・露出)」と「それ以外(細部・ノイズ・鮮鋭化)」に分けて出します。
- **明るさ別・場所別の差**: どの明るさ、画像のどこで差が大きいか。

色空間が違う場合(Photo Pro は撮影時の設定に従うので Adobe RGB になることがあります。x3tif は選んだ色空間)は、
x3tif 側を参照の色空間へ測色的に変換してから比べ、その旨を出力に書きます。同じ色空間ならそのまま比べます。

#### 参照と結果(v0.1.9 以降の作業時点)

- Photo Pro: **SIGMA Photo Pro 6.9.0**(macOS)。設定は既定のまま(MakerNote の記録: 露出 0、コントラスト 0、シャドウ 0、
  ハイライト 0、彩度 0、シャープネス 0、X3 Fill Light 0、カラーモード Standard、WB は撮影時の設定、
  色空間は撮影時の設定 = Adobe RGB (1998)、ノイズリダクション(色・輝度)は既定の中央値、16bit TIFF)。
- 参照は 3 機種 × 5 枚の 15 枚で、すべて ISO 100。
  - dp0 Quattro(ファームウェア 2.03): WB 色温度 5000K、F5.6。同じ日の夕方(暗い場面 1 枚を含む)。
  - sd Quattro(ファームウェア 1.13): WB オート(x3tif は Sunlight として扱う)、F2.8〜6.3。5 枚とも縦位置。
  - DP1 Merrill(ファームウェア 1.04): WB オート、F2.8〜5.6。うち 2 枚が縦位置。
- 縦位置の写真は、Photo Pro は画素を回して書き出し、x3tif は Orientation タグで示します。`tiffcmp` は両方を正立させてから比べます。

機種ごとに合わせた内容:

- **dp0 Quattro**: 露出を 0 EV に固定し、トーンカーブを Photo Pro から測った表に。仕上げは粒状感の除去をやめ、色のぼかしを弱く。
  色温度指定 WB の青のゲインを 1.17 → 1.147。
- **DP1 Merrill**: 露出を 0 EV に固定し、トーンカーブを測った表に。CAMF の表を使ったシェーディング補正(周辺の光量落ちと
  色かぶり)を追加。換算式は CAMF に無いので Photo Pro の出力から求めたもので、灰色に近い部分の色の比のずれの場所による
  ばらつきは、青/緑 0.144 → 0.029 段、赤/緑 0.095 → 0.037 段になりました。赤のゲインの補正は 1.04 → 1.024。
- **sd Quattro**: 露出とトーンは以前の値で合っていました(今回の 5 枚でも ±0.03 段以内)。仕上げだけ、色のぼかしと
  粒状感の除去を弱めて Photo Pro に寄せました。

**Photo Pro とは画素単位では一致しません。** 完全一致は約 1% 以下で、主に白飛び・黒つぶれの画素です。残っている差:

- 高周波(3.0〜11.6/255): 残差の中心です。Photo Pro の解像処理・ノイズリダクション・シャープネスは非公開で、x3tif のものとは
  別物です。Quattro の下 2 層(1/4 の画素数)を上層の解像度へ広げる方法も違います。
- 低周波(2.4〜5.8/255): 色の出方の違い。Photo Pro はカラーモードごとの色補正表(CAMF の `ColorModeCompensations`、
  `MultiAxisTable_*` など)を使いますが、x3tif は使っていません。Merrill のシェーディング補正は色かぶりには合いましたが、
  明るさの周辺落ちは画像によって合い方が違います(必要なゲインの傾きが画像ごとに 2 倍ほど違う)。WB オートの写真では、
  画像ごとに赤・青が 1〜2% ずれます。3x3 の色マトリクスや WB ゲインを当てはめ直しても共通の補正にはなりませんでした。

比較できているのは上の 3 機種・ISO 100 だけです。高感度、ほかの WB、ほかの機種(DP2 / DP3 Merrill、dp1〜dp3 Quattro、
sd Quattro H)については、設定を記録した Photo Pro の参照がまだありません。DP2 / DP3 Merrill にはシェーディング補正だけが
掛かり(同じ形式の表を持つ場合)、露出とトーンは従来のままです。dp1〜dp3 Quattro と sd Quattro H の仕上げは sd Quattro の値に従います。
